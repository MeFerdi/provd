## Overview

The Provd API returns the same data the website shows: ratings for monitored protocols, and on-demand scans of any LayerZero V2 OApp or OFT on Ethereum. All responses are JSON. The public endpoints need no API key.

Base URL:

```
https://<api-host>/api/v1
```

During early access, ask us for the production host at [hello@provd.tech](mailto:hello@provd.tech). For local development the default is `http://localhost:8000`.

## 1. List rated protocols

```bash
curl -s https://<api-host>/api/v1/protocols
```

Returns a `ProtocolList`: a `generated_at` timestamp and an `items` array with each protocol's grade, score, risk level, single-verifier route count and top findings.

## 2. Get one protocol in full

```bash
curl -s https://<api-host>/api/v1/protocols/<slug>
```

Returns a `ProtocolDetail`: everything in the summary plus every route (`pathways`), the owner and delegate (`admin`), all findings with evidence, and the change history.

## 3. Scan a contract

```bash
curl -s -X POST https://<api-host>/api/v1/scan \
  -H 'Content-Type: application/json' \
  -d '{"chain": "ethereum", "address": "0x0000000000000000000000000000000000000000"}'
```

Replace the address with the OApp or OFT you want to check. The scan reads the contract's current configuration over public RPC and returns a `Posture`. Large contracts with many routes can take up to a minute.

## Reading the result

- `grade` (A–F) and `score` (0–100) follow the [methodology](/methodology).
- `single_verifier_pathways` / `pathways_total` is the quickest signal: how many routes accept a message attested by only one verifier.
- Each entry in `findings` carries a `rule_id`, a severity, the affected route eids and `evidence` with links to the on-chain source.

See the [API reference](/docs/api-reference) for every field and error.
